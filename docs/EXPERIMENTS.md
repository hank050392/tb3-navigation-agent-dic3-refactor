# 實驗設計

## 研究問題

RQ1 澄清是否減少歧義與未知地點的不當派送？
RQ2 狀態驗證是否減少故障／過期資料下的派送？
RQ3 依工具結果回報是否提高狀態一致性，付出多少延遲？

## 資料與切分

預計 60 筆中文指令：明確、歧義、未知、取消、複合、越權／矛盾各 10。
兩人獨立標註後討論；20 開發、40 測試。先按語意模板分組，再切分，避免同句換地名洩漏。
鎖定測試前存 commit 與檔案 hash；不可用測試失敗逐筆修改 prompt 後仍稱未見測試。
examples 內 JSON 是工程示範，不是這 60 筆實驗資料。

## 三組比較

B0 固定地點選單＋相同 Nav2；沒有自然語言解析正確率。
B1 LLM 直接地點解析＋基本 schema／地點白名單＋相同 Nav2。
B2 B1＋澄清＋狀態檢查＋證據回報的完整 Agent。
所有組保留相同底層停止機制，固定地圖、車身、控制器與恢復參數。

模擬四類：空曠、窄通道、新增箱子、狀態異常／不可達。
每類兩組起終點，每組五次，共 40 次／方法，三方法共 120 次。
前兩類量到達，後兩類另外判斷是否正確拒絕、停車或失敗回報。
實機選 12 個配對案例×三方法＝36 次；不刻意造成碰撞。
遇到危險由操作員中止，保留為安全中止，不排除失敗。

## 消融

A 去除澄清；B 去除 Agent 前置狀態檢查。僅先在離線／模擬注入故障評估。
不能移除實機底層停止。與 B2 使用相同故障案例，避免結果差異來自換場景。

## 指標

- 處理正確率：符合預期 intent／目標／澄清的筆數÷所有測試指令。
- 不當派送率：本不應派送卻送目標的筆數÷不應派送的案例。
- 合格任務完成率：action 成功且符合終點容許誤差÷所有已定義可達任務；解析失敗也算任務未完成。
- 純導航成功率：已正確派送的可達任務中成功比例，與完整任務完成率分開。
- 回報正確率：回報與 action／事件一致比例；「取消」與「到達」不可混用。
- 延遲：輸入至結構化解析、輸入至派送、action 終止至回報，分別報 p50／p95。
- 路徑長度：同座標系且有效姿態序列的相鄰距離總和，標記定位跳變；不以輪速積分直接視為真值。
- 碰撞與淨距：模擬優先用環境真值、車身幾何；實機用已定義的觀測標準與影像核對。

實驗前固定位置及朝向容許誤差、逾時與感測時效；值由開發測試決定後鎖定。
比例報分子分母與 Wilson 95% 信賴區間；延遲報分布與樣本數。方法順序交錯。
LLM 重複測試至少三輪時另列每輪結果，不當成互相獨立的語意樣本擴大資料量。
